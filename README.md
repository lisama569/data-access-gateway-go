# 本地数据访问策略执行与脱敏审计网关（Go）

一套完全在本地内存中运行的数据访问网关：根据**主体属性、资源敏感级别（数据分级）、
访问目的与授权状态**做出 `允许 / 需脱敏 / 拒绝` 判定，对敏感字段执行**遮蔽或域隔离
的可逆令牌化**，并为每次访问留下**可按当时策略版本与数据分级快照复现**的审计记录。

数据分级是策略判定的一等输入：策略规则可声明适用的**敏感级别区间**，授权可声明
**分级覆盖上限**，结论真正随数据分级变化；重分级对新请求立即生效，但不影响历史
审计按当时分级复现。

- 无外部服务、无网络、无真实凭据；所有数据、策略、授权、保险库、审计均在内存。
- 全部共享结构带锁并做防御性拷贝；`go test -race` 多轮稳定通过。
- 时间可注入（`Clock`），判定是纯函数化的：相同输入（含版本、时间快照）必得相同结论。

## 目录结构

```
internal/model     领域类型：主体/授权/记录/策略版本/规则/结论/稳定原因码
internal/policy    策略版本存储：发布、生效、退役、归档读取（并发安全）
internal/pdp       策略判定点：固定优先级的可解释判定（不触碰字段原文）
internal/masking   字段级遮蔽（不可逆）与令牌化（HMAC + 域隔离保险库）
internal/dataset   内存数据集与授权表（撤销立即生效、深拷贝隔离）
internal/audit     审计日志（不存原文、输入与策略快照、单调 ID）
internal/gateway   组装层：实时读授权/数据 → 判定 → 变换 → 留痕；历史复现
cmd/demo           本地可运行演示
```

## 策略模型

### 主体、授权与资源

- `Subject`：`ID / 部门 / 角色 / 密级(Clearance) / 组`。
- `Grant`：主体对某资源的授权，含**允许目的列表、过期时间、撤销标记、变更时间**。
  授权在每次访问时**实时读取**，撤销（`RevokeGrant`）对下一次请求立即生效，
  审计中保存的是当时授权快照，因此撤销不影响历史复现。
- **授权分级覆盖上限**（新增，`Grant.MaxSensitivity`）：
  - 声明本授权**最多覆盖到**哪个数据分级（闭区间，含该级）；数据分级高于该上限时
    一律拒绝，原因码为独立的 `GRANT_SENSITIVITY_EXCEEDED`，与缺少授权
    （`GRANT_MISSING`）、授权被撤销（`GRANT_REVOKED`）、目的不匹配
    （`PURPOSE_MISMATCH`）、规则分级超范围（`SENSITIVITY_OUT_OF_SCOPE`）等
    现有拒绝明确区分；
  - `MaxSensitivity == nil`（不声明）的**存量授权不做上限检查**，本次扩展
    不会改变其访问结论。
- `Record`：内存记录，含资源标识、敏感级别、**数据保留期 `ExpiresAt`** 与字段表。
  数据分级可通过 `DataSet.Reclassify(resource, level, at)` **原子调整**，
  对之后的请求立即生效。

### 策略版本与规则

- `Policy` 是**不可变版本**：`Version / EffectiveAt / RetiresAt / Rules[]`。
- 规则按数组顺序匹配，取第一条「资源 + 数据分级 + 目的」均命中的规则；
  空列表或 `"*"` 表示通配。
- 规则效果为 `deny / mask / allow`，`mask` 必须携带字段规则（见下）。
- **规则的分级适用范围**（`Rule.MinSensitivity / MaxSensitivity`）：
  - 两者均为 `nil` 时，规则**自身不按分级筛选**；
  - 否则规则只在数据分级落入闭区间 `[MinSensitivity, MaxSensitivity]` 时适用，
    任一边界为 `nil` 表示该侧不设限（如只设 `MinSensitivity` 表示该级及以上）；
    **边界是闭区间**：分级正好压在上/下边界上时仍按该规则正常判定。
  - **写明范围与未声明范围规则共存时的判定（本轮修复的漏放路径）**：
    - 同一资源、同一访问目的下只要存在至少一条写明了分级范围的规则，这些
      写明范围的**并集**就是该资源/目的组合的完整分级覆盖面；
    - 分级落在并集之内时，仍按数组顺序取第一条匹配规则，未声明范围的规则
      在此情形下仍是合法的兜底候选；
    - 分级**落在所有写明范围之外**（调高到超出所有上界，或调低到低于所有
      下界）时，**未声明范围的规则也一律不得生效**，无论其效果是
      `allow / mask / deny`，统一返回 `SENSITIVITY_OUT_OF_SCOPE` 拒绝，
      且**不返回任何数据内容**——不会再出现「分级一路调高反而落到无范围
      规则上照常放行、分级越高结论越松」；
    - 范围只针对**别的目的**时不算本目的的覆盖面（按「资源 + 目的」组合
      分别计算），因此不会误关存量目的的访问；
    - 该资源/目的下**没有任何规则写明范围**（纯存量策略）时，不开启此闸门，
      匹配与结论与扩展前完全一致；
    - 仅当策略里没有任何规则针对该资源时，才返回 `NO_APPLICABLE_POLICY`。
- 版本选择：
  - 默认取请求时刻**已生效且未退役**的最新发布版本；
  - 可通过 `PinnedVersion` 显式固定版本；该版本若尚未生效或已退役，
    返回 `POLICY_RETENTION_EXPIRED`（与普通拒绝原因码不同）；
  - 版本退役后不再服务新访问，但永久归档，供历史复现。

### 判定优先级（结论稳定且可解释）

判定按固定顺序短路，命中因素逐条写入 `DecisionBasis.Factors`：

1. 策略版本选择（固定版本校验生效/退役窗口，否则取当前有效版本）
2. 授权缺失 → `GRANT_MISSING`
3. 授权已撤销 → `GRANT_REVOKED`（授权过期按缺失处理）
4. 数据超出保留期 → `DATA_RETENTION_EXPIRED`
5. **数据分级超过授权上限** → `GRANT_SENSITIVITY_EXCEEDED`（仅授权声明了上限时；
   存量授权无此步）
6. 授权目的不覆盖访问目的 → `PURPOSE_MISMATCH`
7. 主体密级低于规则要求 → `CLEARANCE_INSUFFICIENT`
8. **规则分级适用范围**：分级不在规则声明闭区间内的规则被跳过；同一资源+
   同一目的下存在写明范围的规则、而当前分级不落入任何写明范围时，未声明
   范围的兜底规则（无论 allow/mask/deny）也统一判
   `SENSITIVITY_OUT_OF_SCOPE` 且不返回数据；没有任何规则写明范围则不按
   分级筛选，兼容存量策略。目的不符（第 6 步已先判授权目的，规则侧目的
   不匹配）等更具体的既有拒绝理由不会被该理由顶掉。
9. 规则效果：`deny → RULE_DENIED`；`mask → 需脱敏`；`allow → 允许`
10. 无规则匹配该资源/无有效版本 → `NO_APPLICABLE_POLICY`

其他稳定原因码：`RESOURCE_NOT_FOUND`、`MASK_CONFIG_INVALID`、
`INTERNAL_ERROR`（任何内部错误/panic 都只对外暴露该码，细节不泄露）。

数据保留期过期（`DATA_RETENTION_EXPIRED`）与策略版本保留期
（`POLICY_RETENTION_EXPIRED`）是两个独立、可区分的原因码；数据分级维度的两个新
原因码 `GRANT_SENSITIVITY_EXCEEDED`（授权上限）与 `SENSITIVITY_OUT_OF_SCOPE`
（策略无规则覆盖该分级）同样彼此独立、且与既有原因码都不同。

## 脱敏与令牌语义

字段规则（`FieldRule`）：

- `mask`（遮蔽，**不可逆**）：非空值一律替换为固定常量 `***REDACTED***`，
  不保留长度、前缀等任何原文特征；原始记录不被修改，输出为副本。
- `tokenize`（**可逆、确定性、域隔离**）：
  - 令牌 = `tok_` + base64url(HMAC-SHA256(域密钥, `"v1:"+原文`))；
  - 每个令牌域启动时生成独立随机 32 字节密钥，并拥有独立保险库；
  - **同域**内相同原文恒定得到相同令牌，可通过 `Detokenize(domain, token)` 还原；
  - **跨域**密钥不同、保险库隔离，A 域令牌在 B 域无法还原，也推导不出 B 域令牌；
  - 令牌本身不含原文信息。
- **非法或缺失配置一律拒绝，不静默降级**：未知变换类型、`tokenize` 缺少令牌域、
  字段名为空、字段重复、规则指向记录中不存在的字段，都会使校验/`Apply` 失败，
  网关据此返回 `MASK_CONFIG_INVALID` 拒绝（而不是降级成明文允许）。

## 审计与保留规则

- 每次访问产生一条审计记录（`audit.Entry`），ID 全局单调递增。
- 审计内容包含：主体 ID、资源、目的、结论、**稳定原因码、命中策略版本、
  完整判定依据 Factors、被变换字段名（仅名字）**，以及复现所需快照：
  **策略版本全文、主体属性、授权快照、数据保留期、数据分级快照与记录是否存在**。
- **审计中绝不记录字段原文或令牌**；`Replay` 只返回判定结论，不返回任何数据内容。
- 历史复现（`Gateway.Replay(entryID)`）使用审计内的策略与输入快照，通过一次性
  PDP 重新判定：即使策略已更新/退役、授权已撤销、**数据已被重新分级**，仍按当时
  版本与**当时的分级快照**复现；若复现结论与原审计不一致则返回错误
  （防篡改/防漂移信号）。
- **数据分级变更的一致性与可复现**：
  - `Reclassify` 在数据集写锁内原子完成，对之后的请求**立即生效**；
  - 单次访问在一把读锁内拿到整条记录（含分级），之后使用该本地快照完成判定，
    因此并发重分级与访问交错时，**单次判定不会读到一半旧、一半新的分级状态**——
    结论要么基于旧分级、要么基于新分级；
  - 已产生的审计记录固化当时的分级，后续重分级**不影响历史复现**；新请求则按
    新分级判定。
- 保留期规则：
  - **数据保留期**：记录 `ExpiresAt` 之后的访问 → `DATA_RETENTION_EXPIRED`。
  - **策略保留期**：版本 `RetiresAt` 之后不再服务新访问；固定旧版本访问 →
    `POLICY_RETENTION_EXPIRED`；旧版本始终归档可读，以支撑历史复现。

## 存量兼容范围

本次「数据分级进入判定」为纯增量扩展，默认行为不变：

- **存量策略**：规则不设置 `MinSensitivity / MaxSensitivity` 时不按分级筛选，
  匹配与结论与扩展前完全一致（由 `TestRuleWithoutSensitivityMatchesAllLevels`、
  `TestAllUnscopedRulesLegacyUnaffected` 锁定）。更精确地说，只要某资源/目的
  组合下**没有任何一条**规则写明范围，该组合就完全走存量语义。
- **存量授权**：`Grant.MaxSensitivity == nil` 时不做分级上限检查，任何数据分级下
  结论都不因本扩展改变（由 `TestLegacyGrantWithoutCapUnaffected` 锁定）。
- 只有显式声明了分级区间的规则、或显式声明了上限的授权，才会启用新判定路径；
  新原因码只在这些路径上产生。授权缺失/已撤销、目的不符、密级不足、保留期等
  既有明确拒绝的优先级不变，不会被 `SENSITIVITY_OUT_OF_SCOPE` 顶掉
  （由 `TestOutOfScopeDoesNotOverridePurposeMismatch` 锁定）。

## 并发安全

- 策略存储、数据集/授权表、令牌域保险库、审计日志均以读写锁保护；
  对外返回的记录、授权、审计条目均为深拷贝（含授权分级上限与规则分级区间指针），
  避免调用方修改污染共享状态；
- 每次访问独立构建请求与输出，请求间不共享可变判定上下文；记录在一次读锁内读出后
  使用本地快照判定，并发重分级不会撕裂单次判定；
- 令牌化在写锁内做「同值同令牌 + 冲突检测」，并发下令牌稳定可复现。

## 本地验证方法

需要 Go 1.25+，无需任何外部依赖。

```bash
# 1. 构建
go build ./...

# 2. 运行演示（分级脱敏、同域还原、跨域隔离、重分级变严、历史按旧分级复现）
go run ./cmd/demo

# 3. 全量测试（带数据竞争检测，建议多轮）
go test -race -count=3 ./...

# 4. 只跑分级相关用例并查看输入属性/命中规则/判定依据日志
go test -race -v -run 'Sensitivity|Unscoped|Scope|Reclassify' ./internal/pdp/ ./internal/dataset/ ./internal/gateway/

# 5. 复现本轮漏放路径修复（写明范围 + 未声明范围兜底共存，调高分级必须越界拒绝）
go test -race -v -count=3 -run 'TestSensitivityRaiseBlocksUnscopedFallback|TestEndToEndUnscopedFallbackDoesNotBypassScope|TestConcurrentReclassifyMixedScopeGate' ./internal/pdp/ ./internal/gateway/

# 6. 查看全部带输入属性/命中策略/判定依据的测试日志
go test -race -v ./internal/pdp/ ./internal/gateway/
```

### 演示预期要点

- `confidential` 级访问：`decision=mask`，`name=***REDACTED***`，`ssn=tok_...`；
- 同域可还原 SSN，换一个域还原失败；
- **只把数据分级升到 `restricted`：结论立即变为拒绝**
  （demo 中授权上限为 confidential，因此是 `GRANT_SENSITIVITY_EXCEEDED`；
  去掉授权上限则命中策略最高档 `RULE_DENIED`）；
- 历史审计仍按当时 `confidential` 分级快照复现出 mask 结论；
- 分级降回 `confidential` 后结论恢复脱敏——证明是分级在主导结论；
- **漏放路径**（patient:2002，策略含写明 `public..internal` 范围的脱敏规则与一条
  未声明范围的兜底允许、授权不设上限）：分级在上边界 `internal` 时按写明规则
  脱敏；只调高到 `confidential`（超出所有写明范围）立即变为
  `SENSITIVITY_OUT_OF_SCOPE` 拒绝、`record returned: false`，不会落到兜底
  allow 上放行。
