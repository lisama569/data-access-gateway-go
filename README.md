# 本地数据访问策略执行与脱敏审计网关（Go）

一套完全在本地内存中运行的数据访问网关：根据**主体属性、资源敏感级别、访问
目的与授权状态**做出 `允许 / 需脱敏 / 拒绝` 判定，对敏感字段执行**遮蔽或域隔离
的可逆令牌化**，并为每次访问留下**可按当时策略版本复现**的审计记录。

- 无外部服务、无网络、无真实凭据；所有数据、策略、授权、保险库、审计均在内存。
- 全部共享结构带锁并做防御性拷贝；`go test -race` 稳定通过。
- 时间可注入（`Clock`），判定是纯函数化的：相同输入（含版本、时间快照）必得相同结论。

## 目录结构

```
internal/model     领域类型：主体/授权/记录/策略版本/规则/结论/稳定原因码
internal/policy    策略版本存储：发布、生效、退役、归档读取（并发安全）
internal/pdp       策略判定点：固定优先级的可解释判定（不触碰字段原文）
internal/masking   字段级遮蔽（不可逆）与令牌化（HMAC + 域隔离保险库）
internal/dataset   内存数据集与授权表（撤销立即生效、深拷贝隔离）
internal/audit     审计日志（不存原文、输入与策略快照、单调 ID）
internal/gateway   组装层：实时读授权/数据 → 判定 → 变换 → 留痕；历史复现
cmd/demo           本地可运行演示
```

## 策略模型

### 主体、授权与资源

- `Subject`：`ID / 部门 / 角色 / 密级(Clearance) / 组`。
- `Grant`：主体对某资源的授权，含**允许目的列表、过期时间、撤销标记、变更时间**，
  以及可选的**分级覆盖上限 `MaxSensitivity`**：声明后，数据敏感级别超过该上限
  一律以 `GRANT_SENSITIVITY_CAP` 拒绝（与缺授权/撤销/目的不匹配可区分）；
  `nil` 表示不声明上限，存量授权行为完全不变。
  授权在每次访问时**实时读取**，撤销（`RevokeGrant`）对下一次请求立即生效，
  审计中保存的是当时授权快照，因此撤销不影响历史复现。
- `Record`：内存记录，含资源标识、**敏感级别 `Sensitivity`**、
  **数据保留期 `ExpiresAt`** 与字段表。分级可通过 `Reclassify` 原子调整：
  对之后的请求立即生效，单次读取要么看到旧分级、要么看到新分级，
  不会读到中间状态。

### 策略版本与规则

- `Policy` 是**不可变版本**：`Version / EffectiveAt / RetiresAt / Rules[]`。
- 规则按数组顺序匹配，取第一条「资源 + 目的」均命中的规则；空列表或 `"*"` 表示通配。
- **数据分级进入策略匹配**：规则可声明适用分级范围 `Sensitivity{Min, Max}`（闭区间）。
  当某「资源 + 目的」的候选规则中**存在**声明了分级范围的规则时：
  - 只有范围覆盖当前数据分级的规则可以命中；
  - **未声明分级范围的规则被遮蔽**——数据分级越界时不会误命中泛化的
    允许规则而放行；
  - 所有候选都不覆盖当前分级时，以 `SENSITIVITY_NOT_COVERED` 拒绝
    （与 `NO_APPLICABLE_POLICY` 可区分）。
  候选规则**均未**声明分级范围时，匹配语义与扩展前完全一致（兼容存量策略）。
- 规则效果为 `deny / mask / allow`，`mask` 必须携带字段规则（见下）。
- 版本选择：
  - 默认取请求时刻**已生效且未退役**的最新发布版本；
  - 可通过 `PinnedVersion` 显式固定版本；该版本若尚未生效或已退役，
    返回 `POLICY_RETENTION_EXPIRED`（与普通拒绝原因码不同）；
  - 版本退役后不再服务新访问，但永久归档，供历史复现。

### 判定优先级（结论稳定且可解释）

判定按固定顺序短路，命中因素逐条写入 `DecisionBasis.Factors`：

1. 策略版本选择（固定版本校验生效/退役窗口，否则取当前有效版本）
2. 授权缺失 → `GRANT_MISSING`
3. 授权已撤销 → `GRANT_REVOKED`（授权过期按缺失处理）
4. 数据分级超出授权声明的覆盖上限 → `GRANT_SENSITIVITY_CAP`
5. 数据超出保留期 → `DATA_RETENTION_EXPIRED`
6. 授权目的不覆盖访问目的 → `PURPOSE_MISMATCH`
7. 候选规则存在分级约束但均不覆盖当前数据分级 → `SENSITIVITY_NOT_COVERED`
8. 主体密级低于规则要求 → `CLEARANCE_INSUFFICIENT`
9. 规则效果：`deny → RULE_DENIED`；`mask → 需脱敏`；`allow → 允许`
10. 无匹配规则/无有效版本 → `NO_APPLICABLE_POLICY`

其他稳定原因码：`RESOURCE_NOT_FOUND`、`MASK_CONFIG_INVALID`、
`INTERNAL_ERROR`（任何内部错误/panic 都只对外暴露该码，细节不泄露）。

数据保留期过期（`DATA_RETENTION_EXPIRED`）与策略版本保留期
（`POLICY_RETENTION_EXPIRED`）是两个独立、可区分的原因码。

## 脱敏与令牌语义

字段规则（`FieldRule`）：

- `mask`（遮蔽，**不可逆**）：非空值一律替换为固定常量 `***REDACTED***`，
  不保留长度、前缀等任何原文特征；原始记录不被修改，输出为副本。
- `tokenize`（**可逆、确定性、域隔离**）：
  - 令牌 = `tok_` + base64url(HMAC-SHA256(域密钥, `"v1:"+原文`))；
  - 每个令牌域启动时生成独立随机 32 字节密钥，并拥有独立保险库；
  - **同域**内相同原文恒定得到相同令牌，可通过 `Detokenize(domain, token)` 还原；
  - **跨域**密钥不同、保险库隔离，A 域令牌在 B 域无法还原，也推导不出 B 域令牌；
  - 令牌本身不含原文信息。
- **非法或缺失配置一律拒绝，不静默降级**：未知变换类型、`tokenize` 缺少令牌域、
  字段名为空、字段重复、规则指向记录中不存在的字段，都会使校验/`Apply` 失败，
  网关据此返回 `MASK_CONFIG_INVALID` 拒绝（而不是降级成明文允许）。

## 审计与保留规则

- 每次访问产生一条审计记录（`audit.Entry`），ID 全局单调递增。
- 审计内容包含：主体 ID、资源、目的、结论、**稳定原因码、命中策略版本、
  完整判定依据 Factors、被变换字段名（仅名字）**，以及复现所需快照：
  **策略版本全文、主体属性、授权快照（含分级上限）、数据保留期、
  数据分级快照与记录是否存在**。
- **审计中绝不记录字段原文或令牌**；`Replay` 只返回判定结论，不返回任何数据内容。
- 历史复现（`Gateway.Replay(entryID)`）使用审计内的策略与输入快照，通过一次性
  PDP 重新判定：即使策略已更新/退役、授权已撤销、**数据分级已调整**，仍按当时
  快照复现；若复现结论与原审计不一致则返回错误（防篡改/防漂移信号）。
- **分级变更与复现的关系**：`Reclassify` 之后的请求按新分级实时判定；之前的
  审计记录保存了当时的分级快照，`Replay` 仍复现旧分级下的结论，两者互不干扰。
- 保留期规则：
  - **数据保留期**：记录 `ExpiresAt` 之后的访问 → `DATA_RETENTION_EXPIRED`。
  - **策略保留期**：版本 `RetiresAt` 之后不再服务新访问；固定旧版本访问 →
    `POLICY_RETENTION_EXPIRED`；旧版本始终归档可读，以支撑历史复现。

## 并发安全

- 策略存储、数据集/授权表、令牌域保险库、审计日志均以读写锁保护；
  对外返回的记录、授权、审计条目均为深拷贝，避免调用方修改污染共享状态；
- 分级调整（`Reclassify`）在写锁内原子完成；与访问请求并发时，单次判定
  基于一次一致的分级快照，不会读到一半旧一半新的状态；
- 每次访问独立构建请求与输出，请求间不共享可变判定上下文；
- 令牌化在写锁内做「同值同令牌 + 冲突检测」，并发下令牌稳定可复现。

## 本地验证方法

需要 Go 1.25+，无需任何外部依赖。

```bash
# 1. 构建
go build ./...

# 2. 运行演示（脱敏、同域还原、跨域隔离、策略更新、撤销、历史复现）
go run ./cmd/demo

# 3. 全量测试（带数据竞争检测，建议多轮）
go test -race -count=3 ./...

# 4. 查看带输入属性/命中策略/判定依据的测试日志
go test -race -v ./internal/pdp/ ./internal/gateway/

# 5. 只看分级相关用例（输入分级、命中规则范围、判定依据逐条可见）
go test -race -v ./internal/gateway/ -run 'Sensitivity|Reclassify'
```

### 演示预期要点

- `research` 访问：`decision=mask`，`name=***REDACTED***`，`ssn=tok_...`；
- 同域可还原 SSN，换一个域还原失败；
- 策略升级为 deny 后新访问被拒（`RULE_DENIED`、新版本号）；
- 撤销授权后立即变为 `GRANT_REVOKED`；
- 旧审计记录仍按旧版本复现出 mask 结论；
- 声明了分级上限（internal）的授权访问 restricted 数据 → `GRANT_SENSITIVITY_CAP`；
- `Reclassify` 调低分级后新请求立即按新分级判定，且新审计记录可一致复现。

### 兼容范围

- **存量策略**：规则未声明 `Sensitivity` 时，匹配语义与扩展前完全一致；
  只有同一「资源 + 目的」的候选规则中出现了分级约束，遮蔽与
  `SENSITIVITY_NOT_COVERED` 语义才生效。
- **存量授权**：`MaxSensitivity` 为 `nil`（未声明上限）时不引入任何新拒绝，
  访问结论与扩展前一致。
- **存量数据**：记录未调整分级时按原分级判定；`Reclassify` 只影响之后的
  请求，历史审计记录仍按当时分级快照复现。
